# Accessibility rules

Teamz apps ship with WCAG 2.1 AA as the minimum bar. Every generated UI
must satisfy this list.

## Color contrast

- Body text: ≥ 4.5:1 contrast against its background.
- Large text (≥ 18pt, or 14pt bold): ≥ 3:1.
- Non-text UI (icons, input borders, focus rings): ≥ 3:1.
- Test state + hover + disabled — disabled is often too low; use
  reduced opacity with explicit contrast recomputed, not "just grey".

## Touch / click targets

- Interactive elements ≥ 44 × 44 logical pixels.
- Hit area can extend beyond the visual element (padding is fine) — use
  `Padding`-wrapped `InkWell` in Flutter, `p-3` around a 20px icon on web.
- Space between adjacent targets ≥ 8 px.

## Typography & scaling

- Dynamic Type (iOS) and Font Size preferences (Android) must work — do
  NOT disable text scaling. Test at 200%: layouts reflow, nothing
  truncates important content.
- Line-height ≥ 1.4 for body; ≥ 1.2 for display.
- Never lock `textScaleFactor` below 1.0 or above 1.5.

## Semantics

- Every icon-only button needs a `Semantics(label: …)` (Flutter) or
  `aria-label` (web).
- Read order = visual order. Avoid absolutely-positioned elements that
  fight the natural DOM/widget-tree order.
- Use landmark semantics on web: `<nav>`, `<main>`, `<header>`,
  `<aside>`, `<footer>`. Don't use `<div>` for everything.
- Live regions for dynamic content (loading states, toasts):
  `aria-live="polite"` on web; on Flutter, announce via
  `SemanticsService.announce(...)`.

## Focus & keyboard

- Visible focus ring on every interactive element (kit design system
  provides one; don't remove it with `outline: none`).
- Logical tab order: top-to-bottom, left-to-right. If you use
  `autofocus`, the destination must be predictable and related to the
  action that triggered the screen.
- Escape dismisses modal dialogs and bottom sheets.
- Enter / Space activates buttons; Arrow keys navigate menus.

## Forms

- Every input has a visible label (not a placeholder pretending to be
  one).
- Error messages reference the field by name: *"Email must contain @."*
  rather than *"Invalid input."*.
- Required fields marked both visually (*) and semantically
  (`required` attribute / `aria-required`).
- Don't disable the submit button while a field is empty on first
  render — enable it and show validation on blur, so screen-reader
  users can reach the error.

## Motion

- Honor `MediaQuery.disableAnimations` (Flutter) and
  `@media (prefers-reduced-motion)` (web): skip decorative lerps,
  shrink transition durations to 0–50ms.
- Avoid parallax, zoom-in-on-scroll, and 360° rotations for users with
  reduced-motion enabled.

## Copy / language

- Use plain language. Target 8th-grade reading level for body text.
- Error copy: state what happened, why, what to do next.
- Never use all-caps for more than button labels.
- Internationalize EVERY user-visible string. See the host project's
  `lib/l10n/` (Flutter) or i18n setup (web).

## Screen readers to test against (Phase 9)

- iOS: VoiceOver.
- Android: TalkBack.
- macOS: VoiceOver.
- Windows: NVDA (free, preferred) or JAWS.
- Web: NVDA + Chrome or VoiceOver + Safari.

## Verification before claiming done

- Toggle OS-level dark/light — every screen must stay readable.
- Zoom body text to 200% — no truncation of important content.
- Tab through the entire flow with keyboard only — reach every
  interactive element in a sensible order.
- Turn on a screen reader for the primary flow — every button
  announces, every state change announces.

If any fails, fix before claiming done.
